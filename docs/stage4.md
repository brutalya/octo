# Stage 4 — nodes, E2EE tunnel, remote control

Every installation (PC, VPS, later phone) is a **node**. A **relay** connects nodes that can't reach each other. The relay never sees plaintext and holds no keys. A user's own VPS runs both a node and a relay; a public relay for other people is the same binary with only the relay role.

## Identity & pairing
- Node identity: static X25519 keypair (Noise) + node id = first 16 bytes of BLAKE2s(pubkey), base32. Stored in `<data>/keys/node.key` (0600). Created on first start.
- A **network** = set of paired nodes of one owner. Membership list stored on each node: `{node_id, pubkey, name, added_at}`.
- Pairing (new node B joins A): A shows a one-time code `relay_url#token` (QR later) valid 5 min. B connects to the relay, sends join with the token; A and B run Noise `XX`, then both show a 6-digit SAS derived from the handshake hash; the user confirms on A. After confirmation A sends B the membership list and the **network key** (32 bytes, used for stage 4b sync), and A broadcasts B's pubkey to other members.
- Unpair: remove from list on all nodes; rotate network key (4b).

## Transport
- Relay: WebSocket server (`octo-server --relay-addr <ADDR>`, path `/relay`). Clients authenticate to the relay by signing a relay challenge with their static key (Noise `IK`-style proof or Ed25519 derived — choose the simpler correct one, document it). Relay routes binary frames `{to: node_id, payload}` only between nodes that both registered the same `network_id` (hash of network key's public commitment) — no broadcast to strangers, rate limits per connection.
- End-to-end: each node pair runs Noise `IK` (`snow` crate, `Noise_IK_25519_ChaChaPoly_BLAKE2s`) over relay frames. Rekey per session; replay protection by Noise nonces. Direct LAN/WAN connection is a later optimization (same Noise, different carrier).
- Multiplexing inside a Noise session: stream frames `{stream_id, kind: open|data|end|reset, bytes}`; max frame 64 KB; backpressure via per-stream window.

## Remote control (the 4a deliverable)
- Remote API = the same HTTP API, tunneled: node A's server exposes `/api/nodes` (list members + online status) and `/api/nodes/:node_id/*` which forwards the request over the tunnel to node B's local router (in-process, not via TCP) and streams the response back (SSE works unchanged).
- Authorization: requests arriving through the tunnel are accepted only from member nodes. Policy unchanged and enforced on the target node: private threads/files of B are only usable by B's local providers; tunneled requests may read B's private data only if the requesting node is a member (it is E2EE end to end).
- Web: node switcher at the top of the sidebar (local + members, online dot). Switching re-targets the API base to `/api/nodes/:id`. Pairing UI in settings: "Add device" shows code; "Join" takes a code; SAS is an inline card in Settings → Devices ("Check and allow", buttons Numbers differ / Confirm). A running invite or join has Cancel.

## 4b (next, not now)
Encrypted store-and-forward sync of private files and thread metadata via relay mailbox, encrypted with the network key (XChaCha20-Poly1305), conflict policy last-writer-wins per file version.

## Tests (first)
Noise handshake + transport roundtrip between two in-memory nodes; relay routing isolation (node of another network can't receive frames); tampered frame rejected; replay rejected; SAS equal on both sides and differs under MITM (relay swapping keys); stream mux with interleaved streams + backpressure; tunneled SSE end-to-end with two nodes + relay in one test process; non-member rejected.

## Deviations / decisions
Network layer, crate `octo-net`. All Noise patterns use `snow` 0.10 with `25519_ChaChaPoly_BLAKE2s`; no custom primitives.

**Identity.** `node.key` = raw 32-byte X25519 secret (0600, zeroized in memory); public key derived with `x25519-dalek`. node id = BLAKE2s(pubkey)[..16], base32 lowercase. `network_id` = BLAKE2s("octo-net-id-v1" || network_key). Membership JSON (incl. network key, hex) is written 0600 via temp file + rename.

**Relay auth (decision).** Neither Ed25519 nor a separate signature: the client runs Noise `XX` with the relay (prologue `"octo-relay-v1"`), the relay's fresh ephemeral being the challenge. Messages (WebSocket binary): C->R `[0x01 version] || msg1`; R->C `msg2`; C->R `msg3` with payload = network_id (32 B). msg3 proves possession of the client static key; the relay derives node id from it. After that every WS message is one Noise transport message (so the node<->relay link is authenticated and encrypted even over plain `ws://`; the relay's own key is per process and not pinned, the relay is untrusted). Inner plaintext: `0x10 SEND to(16) payload` (C->R), `0x11 DELIVER from(16) payload`, `0x12 ERROR code` (1 peer unavailable, 2 rate limited, 3 busy), `0x13 READY` (R->C). `from` is set by the relay from the authenticated key. Max payload 65502 B. Routing table is keyed `(network_id, node_id)`; lookups use the sender's network only, so a cross-network target is indistinguishable from an offline one. Duplicate registration of the same (network, node) replaces the older connection. Limits per connection: token buckets on messages (200/s, burst 400) and bytes (8 MiB/s); over limit => **backpressure, never drop**: the relay reserves tokens (the bucket may go into debt) and pauses reading that connection until the debt is repaid, so the sender's WebSocket/TCP window fills and frames arrive in order, just slower; the outbound queue keeps flowing during the pause. A connection continuously over its limit for `abuse_after` (30 s) is closed, as is any malformed frame. ERROR 2 is no longer sent (constant kept as a close reason); ERROR 3 (destination queue full) still reports a drop to the sender; handshake (pre-auth) timeout 5 s; 1024 connections. Connection I/O: the relay runs a reader and a writer per connection concurrently (a slow socket write never stops reads, so bulk traffic in both directions cannot deadlock); a socket write that takes longer than 30 s closes the connection. Keepalive: inner message `0x14 KEEPALIVE` (C->R, no payload, never forwarded, counted against the message bucket); clients send one every 30 s, and an authenticated connection silent for 120 s is closed. Connection permits are owned by the upgrade future, so a failed upgrade releases its slot. Client events `Connected`/`Disconnected`/`RelayError` are best-effort (`try_send`, lost if the queue is full); `RelayHandle::is_online` is the source of truth. The relay decrypts before limiting (implicit Noise nonce).

**Node<->node sessions.** Noise `IK`, prologue `"octo-ik-v1" || network_id`. Frame `[version=1][kind: 1 msg1 | 2 msg2 | 3 transport] || noise`. msg1 payload = u64 BE millisecond timestamp, must strictly increase per peer (anti-replay of msg1); `Sessions::with_store` persists the last timestamp per peer (JSON, 0600, atomic rename) so a replayed msg1 is rejected after a restart. Responder requires the authenticated static key to equal the member key for the relay-reported sender id. Simultaneous connect: a node holding an `Init` slot for P that receives P's msg1 keeps its role if its node id is smaller (returns `Handled::Ignored`), otherwise abandons its Init and responds. Transport uses snow's `StatelessTransportState`: data frame `[1][3][nonce u64 BE][ciphertext]`, sender counter strictly increasing, receiver keeps a 2048-bit sliding replay window (checked before and marked after AEAD success). Dropped or reordered frames (within the window) do not desynchronise the session; replays, too-old nonces and tampering are rejected. AEAD failures do not tear the session down; after 16 consecutive failures the slot is reset and `Handled::Rehandshake(msg1)` is returned for the caller to send. An `Init` slot older than 10 s counts as absent (a lost msg1 cannot wedge the tie-break), a bad msg2 leaves the pending `Init` intact, and `Sessions::forget(peer)` drops the slot and the replay timestamp (to be called on member removal). Fresh ephemerals per session; no in-session rekey yet. Max plaintext 65000 B.

**Pairing.** Code `relay_url#token`, token = base32(host_node_id || 16-byte secret), TTL 5 min, single use (consumed by the first handshake that completes; a failed handshake does not burn it). Both sides register on the relay under network id BLAKE2s("octo-pair-net-v1" || secret). Noise `XX`, prologue `"octo-pair-v1" || secret`, msg3 payload = joiner display name. SAS = BLAKE2s("octo-sas-v1" || handshake_hash) first 4 bytes mod 10^6 (6 digits). Frames `[1][0x21 msg1|0x22 msg2|0x23 msg3|0x24 transport JSON]`. Joiner sends `confirm` only after its user approves; host sends `welcome` (host member, members, network key) only after receiving `confirm` and its own user's approval. Joiner refuses to adopt if it already has members. Membership announcement to other members: JSON `member_added` over an IK session, accepted only from members the receiver trusts `full`, and never overwriting an existing member (an announcement cannot change trust, name or key of a known node; `Membership::add` ignores an existing id and reports `false`). Display names are at most 64 characters (counted as chars) without control characters, checked at every ingress (pairing msg3, welcome, announcements, stored file). The joiner checks the host's static key against the code before sending msg3; the host adds the joiner to its membership only after the welcome was sent. Pairing codes must start with `ws://` or `wss://`; the token secret is zeroized and redacted in `Debug`. Membership changes are saved first and applied in memory only if the save succeeded.

**Mux.** Frame `stream_id u32 BE || kind u8 || body`; kinds 0 open, 1 data, 2 end, 3 reset, plus 4 window (added; body u32 credit). Odd ids = initiator. Initial window 256 KiB per stream per direction, credit returned when the application reads; data over the window, >64000 B, or an empty data frame resets the stream; a data/end/window frame for an unknown id is answered with RESET (once per id). RESET and window frames never block the read loop (overflow queue), and dropping the `Mux` or a `Stream` wakes blocked writers. Stream id exhaustion (2^31 opens) is an error, not a wrap. Max 256 streams. Idle timeout: a stream with no frame in either direction (data, window, end, local read/write) for 60 s (`IDLE_TIMEOUT`, `Mux::with_idle` overrides) is reset and the peer is told, so a stalled or vanished peer cannot pin a stream or its window forever. Consequence: a tunneled request whose response is silent for 60 s is reset (SSE should emit keep-alives).

**Known weaknesses.** There is no per-IP connection cap on the relay (only the global 1024): rely on the reverse proxy for that. The relay (or anyone who knows the pairing network id) can evict a pairing attempt by registering the same node id, and can burn it. SAS has 20 bits (safe only because the code is single-use: one MITM attempt). Anyone who learns a network_id can register on the relay in that network (cannot receive others' traffic, can see presence and send junk). A malicious relay can drop/reorder frames (denial of service), see metadata, and burn a pairing attempt. Relay link and clients use plain `ws://` (no TLS crate; put a TLS proxy in front for metadata privacy). No automatic IK rekey. Backpressure at the relay head-of-line blocks all of one connection's destinations while it is over limit, and a legitimately sustained bulk transfer above the rate for 30 s is closed as abuse. Mux idle timeout also resets legitimately silent long requests (>60 s). Membership removal does not rotate the network key (4b): a removed node can still register on the relay in that network (it cannot decrypt IK sessions of others). The tunnel allow-list/trust check protects data only on nodes that run this code; trust is each node's local opinion, so a compromised full-trust member can announce other members as full to the nodes that trust it.

**Node service & HTTP (4a backend).** `octo-server::node::Node` (state under `<data>/keys/node.key`, `<data>/membership.json`, `<data>/keys/ik_ts.json`) runs one actor that owns the relay client, `Sessions` and one `Mux` per peer; it connects to the relay only when `relay_url` is set and there are members, and rebuilds the link when settings or membership change (`PATCH /api/settings` gains `relay_url` (`ws://`/`wss://`, `""` clears) and `node_name`). Sessions are created on demand; a new session replaces the peer's mux (mux needs an ordered stream, so a dropped relay frame stalls only the affected streams). Mux role is by node id (smaller = initiator). Session plaintext is `0x00 || mux frame` or `0x01 || JSON` (membership announcement). Tunneled exchange = one mux stream: `u32 len || JSON head || body`, response the same; the request body is buffered (<= 51 MB), the response streams chunk by chunk (SSE incremental). **Tunnel authorization (allow-list).** The target accepts only `/api/{threads,providers,files,import}/...` (threads, messages, cancel, models, files, import); every other path (settings incl. GET and PATCH, `/api/pairing/*`, `/api/nodes/*`, unknown paths, `..` or `%` segments) is 403, so new routes are private by default. Header allow-list: request `content-type`, `accept`; response `content-type`, `cache-control`, `content-disposition`, `x-content-type-options`, `content-security-policy`. The bearer token is never forwarded; the target dispatches into a router that has no token layer and no `/api/nodes` or `/api/pairing` routes (explicit 403 for those paths: no hop chains). `GET /api/nodes` pings members (session + `PING` stream, 2 s) for `online`; a failed ping resets the session. `/api/nodes/:id/*rest` forwards to `/api/<rest>`; `:id` = self dispatches locally. API: `POST /api/pairing/invite` -> `{code, expires_at}`, `POST /api/pairing/join {code, name}` (202), `GET /api/pairing/pending` -> `{sas, peer_name}` (404 if none; on the joiner `peer_name` is the host node id until welcome), `POST /api/pairing/confirm|reject`, `GET /api/pairing` -> `{stage: idle|inviting|joining|confirm|finishing, invite: {code, expires_at} | null}` (Settings shows a running invite or join again after being closed), `POST /api/pairing/cancel` (204; ends the running invite or join, its code stops working; no-op when idle). One pairing at a time: `invite` while a code is out returns that same code, otherwise 409. A joiner saves the code's relay URL (key included) as its `relay_url` when the network is adopted. **Network.** `GET /api/network` -> `{joined, name, relay_host, devices}`: a device is in a network once it has a relay or members; `name` is the per-device `network_name` setting (`PATCH /api/settings {network_name}`, `""` resets) or else the relay host. `POST /api/network/create {relay_url, name}` (the relay code; 400 if not `ws://`/`wss://`) saves both and returns the view; `POST /api/network/leave` (204) ends any pairing, forgets all members (new network and private keys), the relay and the name. Create, and `POST /api/pairing/join`, return 409 while the device has members: leave first. Like settings, `/api/network` is not reachable through the tunnel. The host's `network_name` travels in the pairing welcome (optional JSON field `network_name`, ignored by older joiners); the joiner saves it, or clears its own when the host has none. Settings (relay URL, API keys, node name) are not reachable through the tunnel; unpairing and trust changes are local-only API (below).

**Relay exposure (decision).** `--relay` is gone: the relay runs on its own listener (`--relay-addr`) that serves only `/relay` (WebSocket) and `/healthz`; everything else is 404, and the API listener (`--addr`) never serves `/relay`, so publishing the relay never publishes the API. `--relay-only` (requires `--relay-addr`) skips the hub, node and API listener entirely (`deploy/systemd/octo-relay.service`). The server refuses to start when `--addr` is not loopback and no `--token` is set. TLS is terminated by a reverse proxy (`deploy/systemd/Caddyfile.example`).

**Trust levels (decision).** Each member record has `trust: "full" | "public"` (default `public`; old membership files without the field read as `public`). Trust is the local policy of each node; it travels only inside `member_added` announcements and is honoured only when the announcer is `full` for the receiver; an announcement from a `public` member is ignored entirely, and one naming an already known node changes nothing. Two keys: `network_key` (membership, relay `network_id`, every member) and `private_key` (private space sync key, 32 random bytes, epoch counter, stored in `membership.json` as `private_key`/`private_epoch`; the old single-key use for private data is gone). `welcome` carries `private_key{epoch,key}` only when the host chose trust=full for the joiner (`POST /api/pairing/confirm {trust_private: bool}`, body optional = false). A joiner that receives the key marks the host and the members as the host labelled them (host = full); a joiner without it marks everybody `public`. Enforcement is on the target node, in the tunnel dispatcher before the router: `policy::tunnel_allows(trust, &TunnelReq{method, path, thread_space, body_private})` denies (403) for `public` members: any path under `/api/files/private`, any `/api/threads/{id}/...` of a private thread (messages, send, cancel, patch, delete), and bodies naming `space: private` (new thread, import, attachments in a message). `GET /api/threads` is filtered to public threads (`filter_thread_list`; a body that is not a thread array is refused). The caller resolves `thread_space` from the store and `body_private` from the JSON body. `PATCH /api/nodes/:id/trust {trust}` and `DELETE /api/nodes/:id` are local-only (not in the tunnel allow-list). Full -> public: set trust, rotate `private_key` (epoch+1), send `{"t":"private_key",epoch,key}` over IK to the remaining full members, never to the downgraded one (it keeps the old epoch and key). Public -> full: send the current key. Remove: delete the member, reset its session, rotate and send as above (always, even for a public member). A receiver adopts a `private_key` message only from a full-trust member and only if the epoch is newer. `GET /api/nodes` lists `trust` per member (`null` for self). Web: "Private files" switch in the host's SAS card (default off) and one per member, Remove button, lock icon next to full members.

**Trust weaknesses.** The downgraded or removed node keeps every private key and copy it already had: rotation only protects future data (re-encrypting existing private data is 4b). Removal and trust changes are not propagated: other nodes keep their own opinion of the removed member until their user acts, and a removed node still holds `network_key`. Key messages queue only in memory: a full member that is offline during a rotation misses the new epoch until the next rotation or upgrade (no catch-up yet). `private_key` is stored in plaintext in `membership.json` (0600) like the network key. `public` members can still see public threads' existence, provider list, and import session lists of the target.


**Agents permission (audit fix).** Each member record has `agents: bool` (default false; old files read false), separate from `trust`. It is this node's local opinion of whether the member may run CLI agents here and is never announced, sent in a welcome, or taken from one (receivers reset it to false). Without it, a tunneled request is denied (403) when it: creates a thread with a CLI provider (`claude`, `antigravity`), sends a message to or patches a CLI thread, sets `approval` (any value) or `cwd` on any thread, or uses `/api/import/*` (list or import). HTTP providers stay allowed subject to the trust rules. `policy::tunnel_allows(trust, agents, &TunnelReq{method, path, thread_space, thread_provider, body_private, body_agents})` is the single decision; the allow-list (`policy::path_allowed`) lives next to it. API: `PATCH /api/nodes/:id/agents {agents}` (local-only), `POST /api/pairing/confirm {trust_private, allow_agents}` on both host and joiner (both default false), `GET /api/nodes` lists `agents` (`null` for self). Web: a "Run agents here" switch (terminal icon) next to the "Private files" switch per member in Devices, and in the SAS card on both host and joiner (the joiner's card has only this switch). If the thread lookup the policy needs fails (storage error), a non-local caller gets 500 (fail closed). Pairing completion no longer overwrites the live membership with a stale clone: the exchange runs on a detached copy and the result is merged into the live membership under its lock (`Membership::detached`, `adopt_from`, `put`).

**Server hardening (audit fix).** Forwarded (remote) responses: content type from the whitelist `application/json`, `text/event-stream`, `application/octet-stream`, `text/plain` (else `application/octet-stream`), always `nosniff` and `Content-Security-Policy: sandbox`; the remote's CSP and a non-`attachment` Content-Disposition are dropped (`policy::sanitize_forwarded_headers`). A forward body over the limit is 413 (`NodeError::TooLarge`); the tunnel target checks the size before buffering a chunk. 500 responses carry only `{"error":"internal error"}` (detail goes to stderr), as do network errors of the node API. The web UI (embedded and `--web-dir`) is served with `Content-Security-Policy: default-src 'self'; connect-src 'self'; img-src 'self' data: blob:; style-src 'self' 'unsafe-inline'; object-src 'none'; frame-ancestors 'none'` and `nosniff`; an unknown path with a file extension is 404, without one it is the SPA `index.html`. Without a token, requests with a foreign `Host` header are 403 (DNS rebinding). `app`, `app_with_token`, `app_with_node` were collapsed into `app(hub, AppConfig{web, token, node, allowed_host})`. Upload, blob and tunnel body sizes derive from one constant. Token files are fully written to a temp file, then hard-linked into place (atomic); if hard links are denied (`PermissionDenied`, e.g. Android SELinux), renamed if the target is absent (check-then-rename, not atomic against a concurrent creator). The server binary shuts down gracefully on SIGTERM/Ctrl-C (stop accepting, `Hub::shutdown`, exit) and no longer falls back to `CARGO_MANIFEST_DIR` for `web/dist`.
