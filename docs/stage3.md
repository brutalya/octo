# Stage 3 — desktop app (Tauri v2)

Goal: one installable app per OS; no sidecar, no Python, no second process.

## Shape
- New crate `crates/octo-desktop` (Tauri v2). It embeds `octo-core` + the axum router from `octo-server` (move router construction into a lib target `octo-server::app(config) -> Router`, the bin stays a thin wrapper).
- On launch: bind axum to `127.0.0.1:0` (random port) inside the Tauri tokio runtime; webview loads `http://127.0.0.1:<port>/` — same web build, same API, zero frontend forks.
- Security: per-launch random 32-byte token. Server requires header `Authorization: Bearer <token>` on `/api/*` when a token is configured (server bin: optional `--token`; desktop: always). Webview gets the token via an initialization script (`window.__OCTO_TOKEN__`); web client sends it if present. Test: 401 without token.
- Shutdown: on app exit, ProcessRegistry kills all children; axum graceful shutdown.
- Single instance (`tauri-plugin-single-instance`): second launch focuses the window.
- Window: one window, remembers size/position; no tray for now.
- Data dir: same `directories` path as server (`octo`), identifier `com.octo.app`.
- CSP: strict (`default-src 'self' http://127.0.0.1:*; ...`), no remote assets.
- Icons: placeholder generated by `tauri icon` from a plain square; real icons later.

## Build / release
- `cargo tauri dev` for local dev (uses vite dev server).
- GitHub Actions `release.yml` on a push to `main` that changes `crates/octo-desktop/tauri.conf.json` or `Cargo.toml` (or manual dispatch): checks both versions match, creates draft release `v<version>` (skipped if the tag exists), builds desktop with tauri-action (windows-latest NSIS `.exe`, ubuntu-22.04 `.AppImage`/`.deb`) and Android (calls `android.yml`), then publishes the release as latest.
- Updater: wired (`tauri-plugin-updater`, endpoint `https://github.com/brutalya/octo/releases/latest/download/latest.json`) but signing key is a repo secret the owner adds (`TAURI_SIGNING_PRIVATE_KEY`); document the one-time `cargo tauri signer generate` step in README. Build must not fail when the secret is absent (updater artifacts skipped).
- CI (`ci.yml`) runs by changed paths: `rust-linux` (fmt, `clippy --workspace --all-targets`, tests) covers the desktop crate on Linux; `rust-windows` runs only `cargo test --workspace --exclude octo-desktop`. The desktop crate is compiled for Windows by `release.yml`.
